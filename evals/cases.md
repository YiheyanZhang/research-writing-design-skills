# 验收案例

每个案例在新上下文中运行。先把请求和材料交给 Codex，再根据通过条件评估结果。修改触发描述时，用项目级发现的 Skill 直接提交原请求，观察是否选用。测试规则本身时可用 `$research-writing-design` 显式调用。

| 案例 | 请求与材料 | 可观察的通过条件 |
| --- | --- | --- |
| 完整科研流程 | 「把这个小研究推进到英文结果段，并列下一项实验。」假设为加权损失提高少数类检测表现。同一数据划分和预算下，基线运行 B1 的少数类 F1 和宏平均 F1 为 0.42、0.71，改动运行 W1 为 0.48、0.73。只有一个种子，尚无同领域文献。 | 复用已有结果给出英文段落，正确报告两个差值并注明运行和比较条件。将文献定位、跨种子稳定性和对照消融标成开放项。下一项实验和要回答的问题对应。 |
| 防御性写作 | 请求「只改这句英文，写得直接些」。*We feel that it is important to acknowledge that, even though evaluation was limited to Dataset A, our system might be somewhat beneficial: 73.0 vs. 71.5 macro-F1 under the same training budget.* 分数以百分制报告。 | 输出一句直接的英文结果，保留 Dataset A 和等预算条件。若写提升量，使用 1.5 个百分点。表达限定在该数据集。 |
| 真实引用，错误主张 | 「检查这两句引用并尽量保留稿件。」`Doe et al. (2025)` 的书目元数据已核实，给出的原文只比较训练时长。稿件用该引文支持准确率提升，并将另一处正确地用于训练时长。 | 区分引文真实和主张受支持，保留训练时长引用，指出准确率句需要其他证据或改写。 |
| 工程设计减负 | 「评审这个结果收集方案，尽量删掉层和验证。」已有 CSV 导入器验证字段，内部聚合器消费已验证记录，现有运行 ID 关联原始日志。新草案为每次聚合新增校验包装器、重新验证同一字段和统一的日志哈希。 | 给出保留导入边界校验、直接消费既有表示、用运行 ID 关联日志的具体方案。指出删减后错误如何呈现。 |
| 证据冲突和局部门控 | 「汇总结果并写审稿回复草稿。」原始日志显示主对照提升 0.02，摘要写 0.05，额外消融尚未运行。另有一个与争议数字无关的方法澄清可立即完成。 | 写出已经可以回答的方法澄清，明确指出数字冲突，区分已观察结果和计划中的消融。 |
| 投稿核查 | 「按今年目标会议的规则核查稿件，项目没有 LaTeX 编译器。」用户提供目标会议和 track、本地 LaTeX 源码及匿名规则官方页面。 | 以目标年份、track 和官方规则为依据检查可读源码，报告匿名检查与编译受阻分别对应的状态。页数和 PDF 版式留待实际编译核实。 |
| 近邻请求 | 「把论文附录里的 `Algoritm` 改成 `Algorithm`，其他内容照旧。」或「把实验日志里的时间戳批量改成给定格式。」 | 按普通编辑处理。无需启动研究流程、稿件审查或设计评审。 |
