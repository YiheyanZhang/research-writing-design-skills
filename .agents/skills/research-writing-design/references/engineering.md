# 技术设计与实现

1. **找实际入口。** 读当前实现和直接调用方，明确用户要改变的行为、必须兼容的输入输出和已经存在的测试。
2. **选最小完整实现。** 先用本项目已有逻辑，再考虑标准库和既有依赖。每层抽象、配置和引入的新检查都要能解释它对应的当前行为、现实失败或明确的复用需求。
3. **按边界处理错误。** 维持外部输入的必要校验。内部消费已验证数据时沿用当前契约。额外检查需要有可描述的失败场景和实际后果。保留数据写入的一致性、可见的错误和适用的安全要求。
4. **用现有路径验证。** 在正常入口验收请求的行为，保留覆盖边界条件或真实回归的针对性测试。文件或运行已经能通过路径、版本或 ID 定位时，直接用这些信息连接证据。

评审设计时指出具体可删的层、检查和流程，说明删减后由哪个现有位置承担必要行为。如果存在真实的正确性风险，用输入、失败和后果描述它。执行已授权且可逆的调整，按影响范围处理其余依赖。
